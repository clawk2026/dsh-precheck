## SEO 路径实测（用户问「每个插件一个页面，优化 SEO 拿流量再承接可行吗」）
- 收录实测（2026-11-10）：`site:dshprecheck.com` 与品牌词搜索结果里官网页面 0 条，只出现 GitHub 仓库与第三方站 → 实际收录≈0。详情页 `/plugin/liustack/modlens` 抓到的是 `Loading detail…` 空壳，纯 CSR（app.js 无 prerender/SSG/generateStaticParams 关键词，og/document.title 靠 JS 运行时改）。首页有完整 meta/OG/JSON-LD 但只有一套。robots.txt 允许抓取并声明 `Sitemap: https://dshprecheck.com/sitemap.xml`，该地址却重定向到 www、www 版抓取失败 → sitemap 链路存疑。
- **重大新发现：第三方插件目录站已把这条路占完** —— dsh.so（25,524 artifacts / 25,123 安全扫描 / 23,334 安装测试 L4 / 15,553 运行测试 L5 / 14,720 gold trust，更新至 2026-11-07，提供 custom index source 直连 DSH Discover，且已把 dsh-precheck 自己收成 `/artifact/dsh-precheck`）、dsh.plus（中文插件详情页 `/zh/plugins/modlens`）、dsh-plugins.net（Evidence Score 83/100、按 commit 固定、静态检查）。三个站同一插件页均已被搜索引擎收录且排在前面。
- 结论：SEO 拿流量再承接**不可行**，且顺序反了（ailv.run 是先有付费变现闭环再放大 SEO；这里查完风险的用户下一步是去装插件，无产品可承接）。1.5 万页里 67% unknown + 空壳正文 = thin content/doorway 风险；已有三个更厚内容站 + 官方市场将上线，自己是第四名。
- 唯一说得通的小版本：只做 20-50 个「高意图问题页」（静态 HTML，基于 SAFETY.md / publish.md 一手原文），导向「装前查」而非变现；零成本附属动作，非战略。最小技术债：修 sitemap 域名不一致、把 grade+证据写进 HTML、robots 指向正确域。
